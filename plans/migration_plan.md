## 1. System Overview
The `imputeMulti` package, currently implemented in R and C++, will be migrated to a Python library with core computational logic in Rust, exposed via PyO3 bindings. This hybrid approach aims to leverage Python's rich data science ecosystem and user-friendliness while retaining the performance benefits of compiled languages for critical sections. The new package, `imputemulti`, will offer functionalities for multivariate multinomial data imputation using Expectation-Maximization (EM) and Data Augmentation (DA) algorithms, mirroring the capabilities of the original R package.

## 2. Tech Stack & Dependencies

*   **Python:**
    *   **Core:** Python 3.13
    *   **Data Manipulation:** `pandas` for dataframes, `numpy` for numerical operations.
    *   **Class Definitions:** `dataclasses` for immutable data models.
    *   **Testing:** `pytest` for unit and integration tests.
    *   **Build System:** `maturin` for Rust/Python interoperability, `uv` for dependency management.
    *   **Documentation:** `Sphinx` or `MkDocs` with `myst-parser` for Markdown support.

*   **Rust:**
    *   **Core:** Rust (latest stable release).
    *   **Bindings:** `pyo3` for creating Python bindings.
    *   **Numerical Operations:** `ndarray` for efficient array manipulation, `rand` for random number generation.
    *   **Statistical Distributions:** Custom implementations or specialized crates for Dirichlet distribution and other statistical functions if not available in standard libraries.

## 3. Data Schema / Type Definitions

*   **Input Data:** Primarily `pandas.DataFrame` objects. Categorical columns will use Python's `CategoricalDtype`, and missing values will be represented by `numpy.nan` or `None`.
*   **Internal Data (Rust):** Data will be passed to Rust as `ndarray` structures, typically using integer representations of categorical levels for efficiency.
*   **Output Data (Python):**
    *   `ImputeMultiResult` (`@dataclass(frozen=True)`): Represents the outcome of a full imputation, analogous to the R `imputeMulti` S4 class. It will contain the imputed data, method used (EM/DA), number of iterations, final log-likelihood, conjugate prior information, and parameter estimates.
    *   `ModImputeMultiResult` (`@dataclass(frozen=True)`): Represents the estimated model parameters, similar to the R `mod_imputeMulti` S4 class. It will store the method, iterations, log-likelihood, prior, and MLE/posterior mean of parameters.
*   **Parameter Estimates:** Will be returned as `pandas.DataFrame` or `polars.DataFrame` for easy integration with Python's data analysis workflows.

## 6. Potential Edge Cases & Risks

*   **R's `data.frame` vs. Python's `pandas.DataFrame`:** R's `data.frame` handles factors and missing values (`NA`) with specific behaviors that differ from `pandas.DataFrame` categorical types and `numpy.nan`/`None`. Careful conversion, type coercion, and handling of level mappings are crucial to maintain data integrity and consistent behavior.
*   **R's S4 Classes vs. Python `dataclasses`:** Translating the inheritance model and method dispatch of R's S4 system to Python's object-oriented paradigms (specifically using `dataclasses` for immutability) requires careful design to preserve functionality and extensibility.
*   **C++/Rcpp vs. Rust/PyO3 Statistical Equivalence and Code Quality:** Given the directive to improve code quality during the Rust re-implementation, a key risk is ensuring that while the implementation details change, the statistical results (e.g., parameter estimates, imputation accuracy) remain equivalent to the original R/C++ version. This requires thorough validation against the original behavior, not just identical numerical outputs from potentially flawed C++ code, especially concerning floating-point precision, random number generation, and edge-case behavior.
*   **Parallelism Discrepancies:** The R package leverages `parallel::makeCluster` for parallel execution. Replicating this in Rust (`rayon`, `crossbeam`) or Python (`multiprocessing`) requires careful consideration of data serialization overhead and process management across different operating systems. Initial focus might be on efficient single-threaded Rust, with parallelism as a subsequent optimization.
*   **Data Serialization and Deserialization:** The conversion of `.rda` (R Data) files to Python-readable formats (e.g., CSV, Parquet) must be robust and preserve all aspects of the original data, including factor levels and missing value representation.
*   **Vignette Conversion Complexity:** Translating the detailed statistical explanations and R code examples embedded in LaTeX vignettes to Markdown/Sphinx with equivalent Python code will be a significant manual effort. It requires strong domain knowledge to ensure accuracy and clarity for the new target audience.
*   **Comprehensive Test Coverage:** Ensuring that the newly written Python/Rust test suite achieves equivalent or better coverage than the original R `testthat` suite is vital for preventing regressions and validating correctness across all functionalities and edge cases.
